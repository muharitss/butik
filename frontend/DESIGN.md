# Frontend UI Design & Standards Guide (Shadcn UI First)

This document is the mandatory standard and primary reference for all UI development in the boutique frontend application.

---

## 1. Core Principles (The Golden Rules)

### 1. Strictly Shadcn UI — Do Not Build Custom UI

* **DO NOT** create UI components from scratch if an equivalent component is already available in shadcn UI.
* Always check the official shadcn UI component catalog before designing or implementing a new UI element.
* Prefer existing shadcn UI components over custom implementations.

### 2. Use Shadcn Components As-Is

* Components generated by the shadcn CLI inside `src/components/ui/` must be used **as-is**.
* **DO NOT** modify the internal code, default styling, or built-in variants of shadcn components unless there is a critical technical bug that requires a fix.
* Use the existing props and variants provided by each component.

For example:

```tsx
<Button variant="default" />
<Button variant="outline" />
<Button variant="secondary" />
<Button variant="ghost" />
```

### 3. Locked Colors & Typography — Preset `b84ofqjutM`

* This project was initialized using the official preset:

```bash
npx shadcn@latest init --preset b84ofqjutM --template vite
```

* All color variables, border radius values, and typography configuration are already defined in `src/index.css`.
* **DO NOT** modify the existing color palette in `src/index.css`.
* **DO NOT** hardcode custom colors such as:

```tsx
bg-[#...]
text-blue-500
bg-amber-400
text-slate-800
```

* Use only shadcn semantic color tokens provided by the project, such as:

```tsx
bg-background
text-foreground
bg-primary
text-muted-foreground
```

### 4. Developer Responsibility — Layout Composition Only

UI development should focus primarily on **layout composition and positioning**, including:

* Grid
* Flexbox
* Spacing
* Padding
* Alignment
* Sizing
* Responsive behavior
* Content hierarchy
* Component composition

Layout decisions must follow established shadcn UI patterns, such as:

* Dashboard layouts
* Card grids
* Standard headers
* Sidebar layouts
* Form layouts
* Table layouts
* Responsive navigation patterns

Do not introduce unnecessary custom design systems or visual patterns.

## 2. Design System Foundations

### A. Typography

The project's font configuration is already installed and configured.

#### Body / Sans

```tsx
font-sans
```

Uses:

```text
Inter Variable, sans-serif
```

Use it as the default font for application content.

#### Heading

```tsx
font-heading
```

Uses:

```text
EB Garamond Variable, serif
```

Use it selectively for boutique-oriented headings, titles, or other areas that require an elegant/premium appearance.

Do not introduce additional fonts unless explicitly required.

### B. Semantic Color Tokens

Use only the existing semantic shadcn tokens. Do not define new colors.

| Tailwind Token                               | Purpose                                                      |
| -------------------------------------------- | ------------------------------------------------------------ |
| `bg-background` / `text-foreground`          | Main page background and standard text                       |
| `bg-card` / `text-card-foreground`           | Card and container surfaces                                  |
| `bg-popover` / `text-popover-foreground`     | Floating elements such as dialogs, popovers, and dropdowns   |
| `bg-primary` / `text-primary-foreground`     | Primary actions, CTA buttons, and emphasized elements        |
| `bg-secondary` / `text-secondary-foreground` | Secondary actions and alternative buttons                    |
| `bg-muted` / `text-muted-foreground`         | Muted backgrounds, secondary labels, and helper descriptions |
| `bg-accent` / `text-accent-foreground`       | Hover states and selected items                              |
| `bg-destructive` / `text-destructive`        | Destructive actions, warnings, and error states              |
| `border-border` / `border-input`             | Container and input borders                                  |
| `ring-ring`                                  | Accessibility focus rings                                    |
| `bg-sidebar` / `text-sidebar-foreground`     | Sidebar navigation surfaces and text                         |

### Dark Mode

The theme already supports Dark Mode through the `.dark` class.

**DO NOT** create separate manual color styling for Dark Mode.

Use semantic tokens so that light and dark themes work automatically.

## 3. UI Component Workflow

Whenever a new UI element is required for a page or feature, follow this workflow.

### Step 1 — Identify the Required Component

Determine which shadcn UI component is appropriate.

Examples:

* `Card`
* `Dialog`
* `Table`
* `Form`
* `Input`
* `Label`
* `Select`
* `Sheet`
* `Tabs`
* `Avatar`
* `Badge`
* `DropdownMenu`

Before implementing anything manually, verify whether shadcn already provides the required component.

### Step 2 — Install Through the Shadcn CLI

Run the installation command from the `frontend/` directory:

```bash
npx shadcn@latest add <component-name>
```

For example:

```bash
npx shadcn@latest add card dialog table input label select dropdown-menu
```

Do not manually recreate a component that can be installed through shadcn.

### Step 3 — Import and Use Directly

Import components from:

```tsx
@/components/ui/<component-name>
```

Example:

```tsx
import {
  Card,
  CardHeader,
  CardTitle,
  CardDescription,
  CardContent,
  CardFooter,
} from "@/components/ui/card"

import { Button } from "@/components/ui/button"
```

Use the components directly and compose them through layout rather than modifying their internal implementation.

### Step 4 — Icons

Use **`lucide-react`**, which is already installed in the project.

Example:

```tsx
import { Plus, Search, Trash2, Edit } from "lucide-react"
```

Do not introduce another icon library unless explicitly required.

## 4. UI Compliance Checklist

Before finalizing any UI implementation, verify all of the following:

* [ ] No common UI component has been manually recreated.
* [ ] New shadcn components are installed using `npx shadcn@latest add <component>`.
* [ ] Files inside `src/components/ui/` have not been modified unnecessarily.
* [ ] No hardcoded HEX colors (`#...`) are used.
* [ ] No arbitrary Tailwind colors are used, such as `bg-amber-400` or `text-slate-800`.
* [ ] All colors use the existing semantic tokens such as `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`, `card`, etc.
* [ ] Layout uses standard shadcn patterns with consistent Flexbox/Grid structures and spacing.
* [ ] Icons use `lucide-react`.
* [ ] No unnecessary custom design system has been introduced.
* [ ] Dark Mode works automatically through the existing semantic tokens.
* [ ] Existing shadcn components are composed rather than modified.
* [ ] Responsive behavior follows standard shadcn layout patterns.
